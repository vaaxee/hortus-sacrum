  mesurer l'impact de chaque lot.

**Choix tranchés** (l'utilisateur demande d'avancer sans attendre ; chacun reste réversible)
1. Le programme est une **donnée** livrée (`data/programme/programme.json`), lue à chaque lancement comme les recueils, et
   non une suite de migrations dans `seed.ts`. Les réglages de l'utilisateur sont une **surcouche** en base, jamais
   écrasée.
2. La journée est **calculée** à chaque affichage par une fonction pure, `journee(date, contexte)`. Aucune ligne du jour
   n'est stockée.
3. Le vocabulaire des dates (`quand`) est **le même** que celui des fiches d'indulgence (`data/prieres/indulgences.json` :
   `mois`, `jours_semaine`, `dates`, `tempora`), complété de quelques clés.
4. Les pages composées restent d'abord celles de `engine/composer/composer.py` (stables, relues), décrites par leur liste
   de constituants ; la composition à l'exécution les remplace ensuite, lot par lot.
5. Un test d'unicité parcourt **chaque jour de l'année liturgique** et l'intérieur des pages : il bloque toute livraison qui
   fait paraître un texte deux fois.
6. La liste actuelle est **archivée** (historique des versions) puis remplacée ; on garde les ajouts personnels, les durées
   et les rappels.
7. Bréviaire romain et Officium parvum : **résolus hors ligne** en Python, à partir des fichiers de Divinum Officium, vers
   des pièces partagées (psaumes, hymnes) et un plan léger par jour. Le latin d'abord ; le français seulement quand sa
   source ancienne est identifiée.

## 2. Le programme unique

### 2.1 Vue d'ensemble

```
data/programme/programme.json  ──┐   (livré, versionné, `revision` par entrée)
table Dexie « programme »      ──┤   (surcouche : actif, ordre, durée, rappels, ajouts personnels)
contexte du jour               ──┤   (date, jour liturgique, temps, mois, pratiques du plan en cours, roues)
                                 ▼
                 journee(date, contexte)  — fonction pure, app/src/lib/programme/journee.ts
                                 ▼
          Journee { lignes: Ligne[], lectures: Lecture[], insertions résolues, textesDuJour: Set }
                                 ▼
          Aujourd'hui · Imprimer › jour · rappels · bilan · historique · test d'unicité
```

### 2.2 Types

`app/src/lib/programme/types.ts` :

```ts
/** Quand une entrée vaut. Toutes les clés présentes doivent être vraies (ET) ; une liste vaut si l'un de ses éléments
 *  convient (OU). Même vocabulaire que les fiches d'indulgence. */
export interface Quand {
	jours_semaine?: number[]; // 0 = dimanche
	semaines_du_mois?: number[]; // 1 à 5 ; -1 = la dernière
	mois?: number[]; // 1 à 12
	tempora?: string[]; // « Avent », « Carême », « Temps pascal »… (champ `temps` du calendrier)
	dates?: string[]; // « MM-JJ » ou « AAAA-MM-JJ »
	fetes?: string[]; // clé d'office du calendrier (« Sancti/03-19 »), pour une fête mobile ou transférée
	pratique?: string; // vrai les jours d'une pratique du plan (occurrences() de sa règle)
	heure?: 'matin' | 'midi' | 'soir'; // pour les insertions répétées (Angélus)
	sauf?: Quand; // exception
}

/** Choix d'un texte qui varie : selon le jour de la semaine, une roue, le temps. */
export type Choix =
	| string // identifiant de texte fixe
	| { selon: 'jour_semaine'; valeurs: string[] } // 7 valeurs, dimanche d'abord
	| { selon: 'roue'; roue: string } // élément du jour de la roue (pratique de type roue) — un seul texte
	| { selon: 'quand'; cas: { quand: Quand; texte: string }[]; sinon?: string } // temps, mois, fêtes
	| { selon: 'tirage'; parmi: string[]; par_jour: number }; // roulement (ex-jaculatoires du jour)

/** Une section d'une page : un texte entier, ou un extrait borné par des ancres, ou un point d'insertion. */
export type Section =
	| { texte: Choix; titre?: string; depliable?: boolean; extrait?: { de?: string; a?: string }; quand?: Quand }
	| { point: string; titre?: string } // les invités s'y placent
	| { notice: Choix; titre?: string }; // rubrique repliée par défaut (principe 4), jamais comptée en durée

export type Moment = 'matin' | 'journee' | 'soir' | 'heure_fixe';

/** Une pratique du programme. Elle est déclarée une seule fois. */
export interface EntreeProgramme {
	id: string; // « prog:priere-du-matin »
	titre: string;
	revision: number;
	quand?: Quand; // absent : chaque jour
	/** Pratique autonome : une ligne à cocher, qui ouvre sa page. */
	page?: { moment: Moment; ordre: number; sections: Section[]; heures?: string[] };
	/** Pratique insérée : pas de ligne ; ses sections vont au point d'insertion d'un hôte. */
	insertion?: { hote: string; point: string; sections: Section[]; ordre?: number };
	/** Ce qui se lit : une entrée de l'onglet Lecture, comptée dans « Lectures du jour ». */
	lecture?: { section: 'office' | 'ecriture' | 'doctrine' | 'spirituel'; route: string; ordre: number };
	/** Page explicative seulement (onglet Dévotions), jamais dans la journée. */
	explication?: string[]; // identifiants de textes
	rang?: 'praecipua' | 'pia' | 'supererogatoria';
	duree?: number; // minutes, si l'estimation par le texte est fausse (chapelet…)
	rappels?: string[]; // « HH:MM »
	source?: string; // décision ou audit qui justifie l'entrée
}

/** Surcouche de l'utilisateur, table Dexie « programme ». */
export interface ReglageProgramme {
	id: string; // id de l'entrée, ou « perso:<uuid> » pour un ajout personnel
	actif?: boolean;
	ordre?: number;
	duree?: number;
	rappels?: string[];
	quand?: Quand; // l'utilisateur peut restreindre ou changer les jours
	entree?: EntreeProgramme; // ajout personnel complet, ou entrée livrée qu'il a réécrite
	modifieLe: string;
}
```

Règles des insertions :
- un invité **n'a pas de case** : il est coché avec son hôte ; ses indulgences (Enchiridion de 1952 seulement) comptent
  autant de fois qu'il est dit (une insertion répétée à chaque dizaine compte cinq fois) ;
- un invité **sans hôte ce jour-là** (hôte désactivé par l'utilisateur) redevient une ligne à part, au moment de l'hôte :
  rien ne se perd en silence ;
- une ancre (`extrait.de`, `extrait.a`, point situé dans un texte) est une **phrase exacte** du texte, ou un intertitre
  `## …`. Un test vérifie que chaque ancre se trouve dans son texte : si un texte est révisé, la livraison casse au lieu
  d'insérer au mauvais endroit.

Les roues des litanies (`roue:litanies-*`) sont gardées telles quelles : `{ selon: 'roue' }` ne rend **qu'un** texte, ce
qui supprime la cause des litanies multiples. La rotation « don du jour » et « douleur du jour » est une seule rotation
(arbitrage du 19 nov.) : la roue `douleurs-marie` est alignée sur les dons, et la douleur du jour s'affiche dans la même
insertion du soir.

**Mois et temps** (audit § 2.5) : chaque ajout est une entrée `insertion` ou une section `quand` dans une page existante,
jamais une ligne de plus. Exemples : en juillet, `jardin:les-sept-offrandes-du-precieux-sang` dans la page du vendredi ;
en juin, la section du jour de la neuvaine de Liguori (extrait borné par `## Premier jour`… `## Deuxième jour`).

**Pratiques du plan** (`Pratique`, inchangées) : une entrée de programme les relie par `quand.pratique`. Deux cas :
- la pratique **demande ce que la journée fait déjà** (Quinze samedis, Premiers samedis, Douze samedis, Neuvaine du
  Rosaire, Premier mercredi) : elle **annote** l'hôte (une ligne de rappel dans la page du chapelet ou du mercredi :
  « Premier samedi : 3/5 — confession, communion, quart d'heure de méditation ») et se coche avec lui ;
- la pratique **apporte un texte propre** (répons de saint Antoine, neuvaines, acte de réparation du premier vendredi) :
  une ligne, avec **la section du jour seulement**.

Les liens faux de `parPage` (audit § 1.4) sont corrigés dans les données du programme, pas dans `plan.ts` : l'entrée
`prog:plan:treize-mardis-antoine` porte le bon texte (`jardin:les-treize-mardis-de-saint-antoine`).

### 2.6 La journée calculée

`journee(date, ctx)` (fonction pure, `app/src/lib/programme/journee.ts`) :

1. **Entrées actives** : programme livré ⊕ surcouche (`actif`, `quand`, ajouts personnels) ; filtre par `quand` évalué
   sur le contexte (jour liturgique de `data/calendar`, `occurrences()` des pratiques, élément du jour des roues).
2. **Résolution des choix** : chaque `Choix` donne **un** identifiant de texte (ou aucun).
3. **Insertions** : chaque invité actif est rangé au point de son hôte ; sans hôte, il devient une ligne (2.3).
4. **Pages** : chaque ligne reçoit `sections: SectionResolue[]` (texte, extrait, titre, dépliable) — c'est ce que la page
   d'une pratique affiche, à la route `/pratique/<id>?date=…`.
5. **Textes du jour** : ensemble des identifiants résolus, y compris ceux **contenus** dans les pages composées
   (`contient`, voir 2.8) et les invités.
6. **Garde d'unicité** : si un identifiant paraît deux fois, la seconde occurrence est **retirée** de la page qui ne l'a
   pas en propre (invité ou section `quand`), et un avertissement est noté en console. Le test (2.7) empêche que cela
   arrive dans les données livrées ; la garde protège des ajouts personnels.
7. **Durées** : estimées par `app/src/lib/durees.ts`, mais **sans les rubriques ni les notices** (`[r]…[/r]`), avec les
   prières répétées comptées (Pater et Ave de Brigitte, cinq insertions de dizaine) ; une durée de l'utilisateur prime.
8. **Indulgences** : seulement les fiches de `indulgences.json` qui citent l'Enchiridion de 1952 (règle du 19 nov.),
   multipliées par le nombre de récitations.

Sortie :

```ts
interface Ligne {
	id: string; // id d'entrée : sert de clé partout (coches, historique, boucles Svelte)
	titre: string;
	moment: Moment;
	heures?: string[];
	sections: SectionResolue[];
	invites: string[]; // ids des entrées insérées, cochées avec la ligne
	annotations: { pratique: string; texte: string }[]; // pratiques du plan qui qualifient la ligne
	duree: number;
	rang: Rang;
}
```

### 2.7 Garantie d'unicité : le test

`app/src/lib/programme/unicite.test.ts` :

- pour **chaque jour** du 29 novembre 2026 au 27 novembre 2027 (calendrier `data/calendar/2026-2027.json`, plan et roues
  réels), `journee()` ne contient aucun identifiant deux fois ;
- **inclusion** : pour chaque paire de textes du jour, aucun n'est contenu dans l'autre. Méthode de l'audit : fragments de
  12 mots, sans accents ni ponctuation ; un texte est « inclus » si un tiers de ses fragments se retrouve dans l'autre.
  Exceptions déclarées, avec motif, dans `data/programme/formules-communes.json` : Pater, Ave, Gloria, signe de croix,
  « Dignare me » (formules qui structurent les prières sans être des prières du jour) ;
- chaque ancre (`extrait`, point dans un texte) existe dans son texte ;
- chaque identifiant cité existe dans `sources.json` ou `jardin.json` ;
- chaque invité a un hôte déclaré, et chaque hôte le point demandé.

Le test tourne en vitest, en Node, sans navigateur (lecture des JSON de `data/`). Le diagnostic de doublons de ce
document (`docs/audits/ergonomie-2026-11-18.md`) servira de cas d'essai : sur la liste actuelle, le test doit trouver les
10 doublons de la semaine et l'inclusion du samedi.

### 2.8 Ce qui remplace `engine/composer`

`composer.py` colle des blocs du livret et de sources dans neuf pièces `hortus:*`. On le remplace en deux temps :

1. **Lot 3** : chaque pièce `hortus:*` reçoit un champ `contient: string[]` (les identifiants assemblés), écrit par
   `composer.py`. Le test d'unicité s'en sert. Rien d'autre ne change : les pages relues restent celles de l'utilisateur.
2. **Lot 6** : chaque page composée devient une entrée de programme (sections, extraits par ancres, variantes
   `selon`). Exemple, la Triple Couronne du lundi : l'ordinaire jusqu'à l'ancre « On ajoute l'invocation propre »,
   l'invocation de la première couronne, l'ordinaire jusqu'à « Prières finales », les mystères, puis la fin. Quand la
   page produite par le programme est identique (texte normalisé) à la pièce `hortus:*` correspondante, un test le
   vérifie ; la pièce est alors retirée de `sources.json` et `composer.py` supprimé.

Avantage : l'insertion de fin de dizaine, les sections dépliables et la variante du temps se règlent par données, sans
réécrire les textes ; l'utilisateur peut réordonner ou masquer une section dans l'éditeur.

### 2.9 Coches, durées, rappels

- `Coche.elementId` = `Ligne.id` (`prog:…`, `lec:…`, `perso:…`). Une ligne et ses invités se cochent ensemble ; les
  invités ne créent pas de coche.
- Une ligne à plusieurs heures (Angélus) garde `rang` 0, 1, 2 comme aujourd'hui.
- Rappels : `rappels.ts` lit `journee()` au lieu de la table `liste` (fonction `rappelsDu`, dépendance relevée par le
  graphe).
- La jaculatoire du jour n'est plus une ligne : elle s'affiche en tête d'Aujourd'hui (5.2). La toucher crée une coche
  `jac:<id>` ; ses indulgences comptent seulement si sa fiche cite l'Enchiridion de 1952. Le tirage écarte les
  jaculatoires déjà contenues dans les pages du jour (`jac-100`, `jac-33`, `jac-85`, `jac-134`, `jac-70`, `jac-13`,
  calculées par l'inclusion, pas listées à la main).

- `Quand` reçoit `office` (expression régulière sur l'office du jour : samedi saint, Christ-Roi, Fête-Dieu) et `ou` ;
- un point d'insertion peut être placé **dans** un texte hôte (`coupures` : avant une ancre, ou après chaque partie dont
  le titre suit un motif, pour la fin de chaque dizaine) ; la page est alors une suite d'extraits du même texte, sans
  rien recopier ;
- extraits : `section`, `de`/`a`, `phrase`, `retirer` (paragraphes exacts), `rang_du_jour` (partie du jour d'une
  neuvaine) ; `rangs` sur une section limite une pratique du plan à certains jours de la série (préparation de
  Montfort) ;
- pratiques du plan : `plan` du programme, par identifiant sans l'année. Une pratique dont le texte est déjà dit dans la
  journée **annote** la ligne qui le porte (`fusions`) ; la garde ne retire jamais un texte du programme sans le noter
  (`conflits`, vide sur toute l'année) ;
- inclusion : fragments de 8 mots, un tiers au moins retrouvé dans l'autre texte ; formules communes écartées (signe
  de croix, Gloria Patri) ;
- le tirage des jaculatoires appartient à l'écran du jour (lot 2) et n'est pas dans le programme.

Résultat sur l'année 2026-2027 (plan réel) : aucun conflit, aucune inclusion, une seule litanie du programme par jour.

## 3. Remplacement de la liste existante

### 3.1 Migration Dexie (version 4)

```ts
this.version(4).stores({ programme: 'id' }).upgrade(async (tx) => { /* voir ci-dessous */ });
```

Étapes, dans une seule transaction, une seule fois (meta `programme-v1`) :

1. **Archive** : chaque ligne de `liste` est copiée dans `versions` (`table: 'liste'`, `objetId`, `contenu`), et la liste
   entière dans `meta` (`liste-v1-archive` : JSON, date). L'export JSON la contient donc aussi.
2. **Correspondance** des lignes livrées vers le programme (table fixe `CORRESPONDANCE` dans
   `app/src/lib/programme/migration.ts`) :

   | Ancienne ligne | Devient |
   |---|---|
   | `liste:1` Offrande, `liste:2` Prière du matin, `liste:3` Salve, `liste:4` Intentions | `prog:priere-du-matin` (sections et insertions) |
   | `liste:5` Cordon sept Gloria | `prog:cordon-gloria` |
   | `liste:cordon-mercredi`, `liste:8-3` | `prog:devotion-mercredi` |
   | `liste:8`, `8-1` … `8-6`, `liste:17`, `liste:18`, `liste:20`, `liste:24`, `24-1` … `24-6` | `prog:devotion-<jour>` |
   | `liste:12` Angélus | `prog:angelus` (rappels gardés) |
   | `liste:13` Agonisants, `liste:14` Flèche d'or | insertions (rappels reportés sur `prog:angelus` s'ils diffèrent) |
   | `liste:15`, `liste:16`, `liste:19` | `prog:chapelet`, `prog:triple-couronne`, `prog:brigitte` |
   | `liste:6`, `liste:7`, `liste:roue`, `liste:11`, `liste:petit-breviaire` | `lec:*` |
   | `liste:9`, `liste:10` | pratiques du plan (2.4) |
   | `liste:22`, `liste:23`, `liste:25*` | `prog:priere-du-soir` (sections et insertions) |
   | `liste:scapulaire-jahenny`, `liste:jaculatoires` | insertions ; jaculatoire d'ouverture |

3. **Ce qu'on garde** :
   - `duree` réglée à la main → `ReglageProgramme.duree` de l'entrée correspondante (si plusieurs anciennes lignes
     donnent une même entrée, on garde la plus grande) ;
   - `rappels` modifiés → `ReglageProgramme.rappels` ;
   - `actif: false` d'une ligne livrée → l'entrée correspondante désactivée, **sauf** si d'autres anciennes lignes actives
     y mènent (la prière du matin n'est pas éteinte parce que la ligne Salve l'était) ;
   - lignes `origine: 'personnel'` → ajouts personnels (`perso:<id>`), avec leurs textes, jours (`quand.jours_semaine`),
     rappels, durée et moment ; elles passent elles aussi par la garde d'unicité ;
   - ligne livrée dont l'utilisateur a **changé les textes** (`original !== contenu`) : les textes qui ne sont pas déjà
     dans le programme deviennent un ajout personnel « (repris de l'ancienne liste) ». Rien de ce que l'utilisateur a
     choisi ne disparaît sans trace.
4. **Coches** : inchangées. L'historique traduit les anciens `elementId` par la même table `CORRESPONDANCE` ; un jour
   ancien coché sur « Salve Regina » compte pour la prière du matin.
5. La table `liste` n'est plus lue que par l'Historique (anciens jours) et l'éditeur de versions. Elle est vidée au
   lot 7 seulement, quand l'Historique lit l'archive.
6. Synchronisation (`sync.ts`) : nouvelle collection `programme` ; `liste` cesse d'être envoyée.

## 4. Navigation et écrans

### 4.1 Les onglets

```
┌──────────────────────────────────────────┐
│  ‹ jeu. 19 nov. ›                    (☩) │  ← icône Profil, en haut à droite, sous l'encoche (safe-area)
│                …                         │
├──────┬────────┬────────┬─────────┬───────┤
│Aujour│Lecture │Prières │Dévotions│Calen- │
│d'hui │        │        │         │drier  │
└──────┴────────┴────────┴─────────┴───────┘
```

- Onglets : Aujourd'hui `/`, Lecture `/lecture`, Prières `/prieres`, Dévotions `/devotions`, Calendrier `/calendrier`.
- **Profil** : icône fixe en haut à droite, dans `+layout.svelte` (`top: calc(env(safe-area-inset-top) + 8px)`), 44 × 44 px.
  Elle ouvre `/profil`, **un seul** profil :
  - en tête, le profil spirituel (sacrements, consécrations, patron, saints aimés) ;
  - puis des entrées : Historique, Couronnes, Fêtes personnelles, Imprimer, Réglages ;
  - `/reglages` ne garde que la technique : compte, rappels, apparence, sauvegarde, corbeille. Les éditeurs (programme,
    pratiques, fêtes) sont atteints depuis la page qu'ils règlent.
- Grand écran (`.sommaire`) : mêmes cinq entrées, Profil en bas de la colonne.
- La roue quitte le Profil : sa page reste à `/roue`, atteinte depuis Dévotions et depuis Lecture › Spirituel.

### 4.2 Aujourd'hui

De haut en bas :

1. Date et navigation (inchangées), arche du saint (déjà refaite).
2. **Jaculatoire du jour** : une ligne en italique, différente à chaque ouverture (tirage sans remise sur la journée,
   gardé en `localStorage`), avec l'indulgence de l'Enchiridion s'il y en a une. Toucher : « dite », coche `jac:<id>`,
   petite confirmation, nouvelle jaculatoire au prochain affichage.
3. **Une ligne « Bilan »** : « 7 / 14 · 52 min restantes ». Toucher déplie les jauges (jardin, temps, indulgences 1952) et
   le bilan des étiquettes ; replié par défaut, état gardé par jour.
4. **La liste**, par moments (Matin, Journée, Soir), une ligne par pratique, sans étiquettes ORD./PIA. Sous le titre : la
   variante du jour (« Chapelet — mystères glorieux ») et les annotations du plan (« Premier samedi 3/5 »).
5. **Lectures du jour (2/4)** : une ligne, après la journée, avant le soir.
6. Martyrologe : replié en une ligne « Saints du jour : 7 invocations » ; dépliable.
7. En bas, « Régler le programme » (lien discret), qui ouvre `/programme` ; les trois seuils y sont, en français :
   « Tout », « Sans le surérogatoire », « L'essentiel ».

Estimation : 2 écrans au lieu de 5,5 ; 9 à 11 lignes au lieu de 23 à 26.

### 4.3 Page d'une pratique

`/pratique/[id]?date=…` : titre, variante, puis les sections. Une notice ou une rubrique longue est **repliée**. Les
heures d'un office **ne sont pas toutes sur la même page** (consigne de l'utilisateur, rappelée le 21 nov.) : une rangée de
**boutons d'heures** en haut de la page (Matines, Laudes… Complies), une seule heure affichée à la fois, l'heure courante
choisie à l'ouverture ; chaque heure se coche. Bouton « Fait » en bas
(et case en haut), qui coche la ligne et ses invités. Les liens « autres mystères » du chapelet sont gardés.

### 4.4 Lecture

`/lecture` : quatre cartes, avec l'état du jour (lu / à lire) et la lecture proposée.
- **Office** : choix du bréviaire (Petit bréviaire du Sacré-Cœur, Bréviaire romain, Officium parvum) ; le choix « du
  jour » est un réglage (par défaut le Petit bréviaire). Heures canoniales en **boutons dans la page** (Matines… Complies) :
  une seule heure affichée à la fois, l'heure courante à l'ouverture (consigne de l'utilisateur, 21 nov.).
- **Écriture** : l'Évangile du marque-page (`/ecriture` actuelle), « J'ai lu ce chapitre ».
- **Doctrine** : la Somme, article suivant ; latin en regard (dépliable sur iPhone).
- **Spirituel** : méditation du jour, office et vie du saint (avec la prière de sainte Gertrude à la fin), Guéranger,
  verset des roues ; Visites au Saint-Sacrement en avril.

Les routes actuelles (`/meditation`, `/saint`, `/ecriture`, `/recueils`) sont gardées et reliées ; `/lecture/*` les
englobe sans les réécrire au début (lot 1).

### 4.5 Prières : filtres

- Recherche (en place) ; puis deux rangées de pastilles, défilantes horizontalement :
  - **Thème** (objets du cadre pratique, `etiquettes.ts`) : Trinité, Jésus-Christ, Eucharistie, Sacré-Cœur, Passion,
    sainte Vierge, saint Joseph, Anges, Saints, Âmes du purgatoire, sainte Face ;
  - **Type** : Litanies, Chapelets et couronnes, Offices, Neuvaines, Actes et offrandes, Jaculatoires, Hymnes et
    antiennes. Le type est déduit de la `partie` et du titre (table dans `etiquettes.ts`), corrigeable dans la fiche.
- Les parties sont **repliées** ; le nombre de prières est affiché ; rendu paresseux (une partie n'est rendue qu'ouverte).
- « Méditations » quitte les filtres de Prières pour Lecture › Spirituel.
- Mêmes filtres de thème dans Dévotions et dans la recherche du livret à imprimer.

### 4.6 Dévotions

Sections : **En cours** · **Ce mois-ci** · **Plus tard** (repliée, groupée par mois) · **Pages explicatives** (cordon,
scapulaire, Heure sainte, Garde d'honneur, Milice angélique, acte héroïque, pratiques à jours comptés) · Passées et
corbeille. Les boutons d'administration (ajouter, reprendre le plan) descendent en bas. « 1 jours » corrigé.

### 4.7 Page d'erreur

`app/src/routes/+error.svelte` dans le gabarit de l'app : « Cette page n'a pas pu s'afficher », le message réel
(`page.error.message`), un bouton « Copier le rapport » (message, page, date, version), un lien vers Aujourd'hui.
`app/src/hooks.client.ts` : `handleError` qui renvoie `{ message: String(error.message ?? error) }` et le note en
console.

### 5.2 Format des fichiers

- Sections `[Nom]` ; variantes de section conditionnelles `[Nom] (rubrica cisterciensis)` ;
- renvois `@Fichier:Section` (avec `:N` pour une ligne, et substitutions `s/…/…/`) ; `@:Section` dans le même fichier ;
- appels `&psalm(118,1,8)` (psaume, versets), `&teDeum`, `&Dominus_vobiscum`… et prières communes `$Pater noster` ;
- conditions en ligne : `(sed rubrica 1955 aut rubrica 196 omittitur)`, `(sed tempore paschali)`, `(deinde dicitur)` ;
- `[Rule]` : directives du calcul de l'office (« Psalmi Dominica », « Omit Suffragium »…), interprétées par le Perl de
  DO.

### 5.3 Méthode d'import hors ligne (proposée)

1. **Récupération ciblée**, une fois, dans `vendor/do` (non versionné) : clone partiel
   `git clone --depth 1 --filter=blob:none --sparse`, puis
   `git sparse-checkout set web/www/horas/Latin/{Tempora,Sancti,Commune,Psalterium,Martyrologium} web/www/horas/Francais/{…} web/www/horas/Ordinarium web/www/Tabulae`.
   Ordre de grandeur attendu : quelques milliers de fichiers texte, **10 à 30 Mo** pour les deux langues (à mesurer au
   premier clonage) ; les dossiers des ordres et des autres langues ne sont pas pris. Le dépôt garde seulement les
   **sorties** (5.4).
2. **Résolveur Python**, `engine/office/` (réutilise `do.py`) :
   - `lire.py` : sections, renvois, substitutions, variantes conditionnelles (`cond_true` avec la version « Divino
     Afflatu - 1954 », et `tempore …` selon le jour) ;
   - `heures.py` : l'ordinaire (`Ordinarium/*.txt`) de chaque heure, rempli par l'office du jour (calendrier déjà calculé
     dans `data/calendar`) : Matines (3 nocturnes ou 1 selon le rang), Laudes, Prime, Tierce, Sexte, None, Vêpres,
     Complies ; psautier de saint Pie X (*Divino afflatu*, 1911), commémoraisons, suffrages, preces fériales ;
   - `parvum.py` : l'Officium parvum, en trois variantes de temps ;
   - **contrôle** : pour 20 jours tests (dimanche ordinaire, férie, double de 1re classe, vigile, Quatre-Temps, octave,
     Semaine sainte, jour de commémoraison), comparaison mot à mot avec la sortie du site Divinum Officium (version
     « Divino Afflatu ») enregistrée à la main une fois dans `engine/office/temoins/`. C'est le seul garde-fou réaliste
     contre une erreur de rubrique.
3. **Rubriques d'avant 1955** : version DO « Divino Afflatu - 1954 » (déjà celle du calendrier), qui exclut les
   simplifications de 1955 (`rubrica 1955 … omittitur` est donc **gardé**, Ave et Pater compris) et celles de 1960.

### 5.4 Format de sortie (dans le dépôt, livré à l'app)

Pour tenir dans une PWA sans dupliquer les psaumes 365 fois :

```
data/office/pieces/psaumes.json        { "ps:53": { "la": "...", "fr": "..." }, ... }   (≈ 150 psaumes + cantiques)
data/office/pieces/communs.json        hymnes, capitules, oraisons, antiennes, répons réutilisés
data/office/jours/2026-2027/MM-JJ.json { "office": "...", "heures": { "matines": [blocs], "laudes": [...], ... } }
data/office/parvum.json                { "ordinaire": {...}, "avent": {...}, "noel": {...} }
```

Un bloc : `{ "ref": "ps:53" }` (pièce partagée), ou `{ "type": "antienne", "la": "...", "fr": "..." }` (propre du jour),
ou `{ "rubrique": "..." }`. Estimation : pièces partagées 1 à 2 Mo, plan d'un jour 5 à 15 Ko, soit 3 à 6 Mo par an et
par langue. Les jours sont chargés **à la demande** (`fetch`) et mis en cache par le service worker ; les sept jours qui
viennent sont préchargés à l'ouverture. Rien n'est mis en IndexedDB : ce sont des données livrées, non modifiables
(l'utilisateur peut toujours copier une heure dans ses prières).

### 5.5 La traduction française

Les fichiers `Francais` de DO ne disent pas, fichier par fichier, de quelle édition ils viennent. Or la consigne exige une
source ancienne identifiée. **Choix tranché** : le Bréviaire romain s'affiche d'abord **en latin seul** ; le français
n'est montré que pour les pièces dont la source est établie (les leçons déjà extraites, déjà affichées sur `/saint`,
suivent la même règle que ce qui existe). Pistes pour le Petit office : une édition latin-français ancienne (XIXe ou
début XXe s.) sur Gallica ou archive.org, à recopier comme les autres recueils (rôle Transcripteur).

### 5.6 La Somme (Lachat)

`data/somme/<partie>-<question>.json` : `{ ref: "Iª q. 1 a. 1", titre: {la, fr}, objections: [{la, fr}], sed_contra,
respondeo, reponses: [...] }`. Marque-page : meta `marque-somme` (dernier article lu), comme le marque-page des Évangiles.
Source : traduction Lachat (Vivès, 1856) et texte latin de l'édition léonine ou de l'édition qu'elle accompagne ; à
recopier par le Transcripteur, en commençant par la Iª pars, q. 1-13.

## 7. Questions pour l'utilisateur

Les arbitrages du 19 novembre sont appliqués ; ces questions restent ouvertes, avec le choix fait par défaut.

1. **Office compté dans « Lectures du jour »** : le Petit bréviaire du Sacré-Cœur par défaut, le Bréviaire romain ou le
   Petit office sur réglage. *Par défaut : Petit bréviaire.*
2. **Bréviaire romain en latin seul** tant que la source de la traduction française de Divinum Officium n'est pas
   établie. Acceptez-vous ce temps de latin seul, ou connaissez-vous une édition bilingue ancienne à transcrire ?
3. **Heures du bréviaire** : faut-il des rappels aux heures canoniales (Prime 6 h, Tierce 9 h, Sexte 12 h, None 15 h,
   Vêpres 18 h, Complies 21 h), ou aucun ? *Par défaut : aucun.*
4. **Lignes de l'ancienne liste que vous avez modifiées** : elles deviennent des ajouts personnels quand leurs textes ne
   sont pas déjà dans le programme. Préférez-vous les revoir une à une à la bascule ? *Par défaut : reprise automatique,
   avec une page « Ce qui a changé » à la première ouverture.*
5. **Jaculatoire d'ouverture** : seulement celles de l'Enchiridion de 1952 en traduction approuvée (Thésaurisons 1941),
   ou toutes celles de la bibliothèque, indulgence affichée seulement quand elle compte ? *Par défaut : les premières.*
6. **Seuils** (« Tout », « Sans le surérogatoire », « L'essentiel ») : les garder ? Avec le programme, la journée tombe
   d'environ 2 h 40 à 1 h 40 ; un seul réglage « jour chargé » suffirait peut-être.
